# Implementation plan

See [SPEC.md](SPEC.md). Which phases are done is tracked only in
[HANDOVER.md](HANDOVER.md) ("Current state"). Each phase ends with:
- its unit tests passing (`uv run pytest`, and `npm test` where JS is involved);
- lint and format clean (`uv run ruff format . && uv run ruff check .`,
  `npm run format && npm run lint`), as CI checks;
- a commit on `main`;
- [HANDOVER.md](HANDOVER.md) updated in the same commit.

Tests are written alongside the code, not after it.

## Phase 0 — Skeleton and spikes
- `uv init` package layout (`chgk/` at repo root, `tests/`), `pyproject.toml` with dev deps,
  `.gitignore` (`state.json`, `out/`, `.venv`).
- CI workflow (pytest + `npm test`; later lint and format checks).
- Shared test vectors folder `tests/vectors/`.
- Spikes (throwaway, findings noted in `docs/spikes.md`):
  1. POST from a GitHub Pages page to an Apps Script web app (CORS, `text/plain`,
     a 200 KB photo payload).
  2. QR library on iPhone Safari: scan speed on a 0.65″ code; frame capture
     resolution.
  3. A single printed test card on a real printer.
- **Tests:** a trivial import test, so CI is green from day one.

## Phase 1 — Config, identity, card PDF (works offline)
- `chgk.config`: dataclasses, validation, numbering (`question → round`, spares).
- `chgk.ids`: QR payload encode/decode; `team_id` assignment.
- `chgk.cards`: layout geometry, rendering, the three imposition modes, the
  interactive mode prompt, the test page.
- Teams come from a local file until Phase 2 (now `teams.py`, Python like config.py).
- Font bundled under `chgk/assets/fonts/` (OFL).
- **Tests:**
  - config edge cases (1 round; uneven rounds; 0 spares);
  - payload round-trip against the vectors;
  - imposition properties for all modes over many (teams, questions, grid) combos;
  - geometry (margins, QR minimum size, no overlap);
  - PDF smoke: page count, Cyrillic text, QR decoded from the rendered pages.

## Phase 2 — Apps Script backend + Sheet
- `apps_script/logic.js` (pure, Node-testable): request validation, token check,
  last-write-wins merge, status ↔ cell value, idempotency.
- `apps_script/Code.js`: `doPost` / `doGet`; `create_tournament` (the Sheet built by
  code + Drive folder), `get_teams`, `set_teams`, `record_events`, `get_state`,
  `get_results`, and later `get_board`, `set_board_token`, `share_view`; `onEdit` → Log.
  (`upload_photo` is Phase 4.)
- Results formulas: round sums, total, place. «Статистика» tab.
- Admin token: generated by the script's setup function and kept in Script Properties.
- Switchable Google account (SPEC §3.1):
  - named backend profiles in `~/.config/chgk/backends.json`, with CLI
    `backend add|use|list|check`;
  - the tournament's `state.json` records its backend URL;
  - the jury link carries the backend URL;
  - `docs/google-account.md` covers deploying under another account
    (`chgk backend bundle`, then paste `Code.gs` into the script editor).
- Python `chgk.backend` client; CLI `new`, `teams`; the jury link is printed by `jury-sheet`.
- **Tests:**
  - `npm test` for `logic.js` (merge cases from the shared vectors);
  - pytest for the client with `respx`;
  - pytest for backend profiles: add/use/list, a tournament keeps its backend after
    the active profile changes, nothing written inside the repo;
  - `npm test` for Code.js against in-memory fakes of Sheets/Drive/properties;
  - manual check: deploy once and run `chgk new` against it.

## Phase 3 — Scanner web app
- `web/s/`: pure modules `payload.js`, `queue.js`, `session.js` (missing teams,
  warnings), plus thin UI and camera glue.
- Setup via the jury link (or by scanning it in the app); the current question follows
  the scans; ✓/✗/? flow; spare card asks for its question; missing list; sync pill;
  offline reload (service worker); backend skips re-sorting when the order is unchanged.
- GitHub Pages deployment.
- **Tests:**
  - `npm test` for the pure modules (payload vectors shared with Python; queue
    retry/dedupe; missing list; warnings);
  - integration: the phone modules against the fake backend;
  - headless Chrome end to end (fake camera with real cut-out cards);
  - live check against the user's backend; manual iPhone checklist.

## Phase 4 — Card photos
- Frame capture at scan; JPEG compression; separate upload queue; Drive storage;
  photo link in Log.
- **Tests:** queue ordering (marks never wait for photos); upload-retry logic;
  backend photo request validation.

## Phase 5 — Projector board + stats polish
- `web/b/`: read-only board token; standings of the rounds revealed so far (revealed by
  hand after each round, SPEC §10.1), round sums, «Взяли» per question; QR codes of the
  view-only table and of the board itself (the jury sheet's links).
- **Tests:** ranking/sorting and tie display logic in a pure module (`npm test`).

## Phase 6 — Logos (decisions: user, 2026-10-30; started only when the user says)
- Done earlier: provided PNG/JPG files → pale greyscale (Pillow); shade chosen from the
  test page; shared private library `logos/` with the fallback owl.
- SVG files wherever PNG is accepted (rasterised, then the same pale step; lettering in
  the cards' font PT Sans; unsafe SVGs refused). `chgk logos <folder>`: which logo each
  team's cards use, missing or broken files.
- Claude-drawn SVG drafts in the style of the existing logos (the ЧГК owl acting out the
  team name, question marks / hourglass, flat light grey, the name in bold capitals
  below): `chgk logos <folder> --draw` calls the Claude API with the existing logos as
  references; without an API key it writes a brief (`out/<slug>/logo-brief.md`) for
  drawing them in a Claude Code session instead.
- The API key is never in the repo: `chgk key set anthropic` stores it in
  `~/.config/chgk/` (owner-only), `ANTHROPIC_API_KEY` overrides it, `chgk key status`.
- Preview, then accept: drafts in `logos/drafts/<slug>/`, a preview PDF on real cards at
  the tournament's shade, `chgk logos <folder> --accept all|A01,A02` records them in
  teams.py; `--draw --team A01` redraws one.
- **Tests:** processing invariants (greyscale, max darkness, transparent → white, aspect
  kept), SVG rendering and refusal of unsafe SVGs, the API with mocked HTTP (no real
  calls; key never logged), the no-key brief, preview and accept.

## Phase 7 — Internal test at home, with printouts
- Print real card sets and the jury sheet; run a mock game at home with the iPhone
  scanner, the Sheet, the board and card photos (docs/manual-checks.md and more).
- Write down the feedback as it comes (what failed, what was slow or confusing).
- Analyse each failure or bug, fix it, with a test that would have caught it.
- Finish with a thorough check of the docs, comments, memory and HANDOVER.

## Phase 8 — External test at a tournament with teams
- A real tournament: registered teams, printed decks, jury phones, the projector board.
- The same loop as Phase 7: tests on the day, feedback entry, failure and bug analysis,
  fixes, then a thorough check of the docs, comments, etc.
